## 六、评审反馈修复（W2.1）

首轮体验反馈的两个问题，都已修复并补测试。

### 1. 搜索「一章只出一条、跳不到命中文字」

**原因**：FTS5 天生是文档级命中（一章一条），而"跳到文字"当时直接没做，属于遗漏而不是取舍。

**改动**：

- `modules/search.ts` 命中后回到纯文本里展开：同一章最多 5 处，每处一条结果，带各自上下文
- `SearchHit` 增加 `id`（`refType:refId:occurrence`）与 `occurrence`，面板显示"第 N 处"
- 新增 `shared/editor-doc.ts#findTextRanges`：把纯文本命中换算成 ProseMirror 位置
- 点击结果 → `searchTarget` 写入 store → 编辑器挂载后 `setTextSelection` + `scrollIntoView`，直接选中并滚动到该处
- 只命中标题、正文里没有的情况仍保留一条结果，不会"搜到了却消失"

### 2. 首章是「第一章」，第二章变成「第2章」

**原因**：建项目时硬编码「第一卷 / 第一章」，之后新增却用 `` `第${count + 1}章` `` 生成阿拉伯数字，两套规则。

**改动**：

- 新增 `shared/chinese-number.ts#toChineseNumber`（1–9999，处理「十一」「二十」「一百零一」这类读法）
- `createProject`、`createChapter`、`createVolume` 统一走同一套中文数字
- 已有项目里的旧标题不会被自动改写（可能是用户手动改过的），需要时手动重命名

## 七、W2.2 快照恢复「无限套娃」修复

**现象**：每恢复一次快照，就多一条「恢复前」记录；恢复 A 留 B、恢复 B 留 A……列表无限增长。

**定性**：「恢复前留档」本身是设计（让恢复可撤销），但**没有去重、没有上限**是实现缺陷，属于 bug。

**修复**：

1. **按内容去重**：恢复前先算当前正文的 hash，若本章已有同内容的**耐久**快照（手动 / 恢复前），不再重复写入。
   - 只与「耐久」快照比对：自动快照会被保留策略裁掉，不能作为"内容已留档"的依据。
2. **给「恢复前」加上限**：每章最多 20 条、30 天，超出按时间裁剪（`PRE_RESTORE_KEEP`）。
3. 目标版本与当前内容相同（hash 相等）时直接跳过，不产生任何新记录。

**效果**：在两个版本之间反复恢复，`pre_restore` 最多 1–2 条且不再增长；手动快照仍然永不自动清理。

**验证**：新增 4 条用例（重复恢复同版本只留 1 条、来回恢复 10 次仍 ≤ 2 条、上限裁剪、同内容判定只看耐久快照）。全量 **14 文件 / 99 用例** 全绿，`tsc` / `eslint` / `build` 均通过。

## 八、W2.3 快照备注与删除

**备注输入**：原先备注是侧栏里的一行 input，实测无法输入。改为「＋ 给当前正文留个快照」打开弹窗：

- 弹窗内 textarea 自动聚焦，可写多行备注；
- Enter 保存、Shift+Enter 换行、Esc 取消；
- 回车提交带 \isComposing\ 判断，中文输入法上屏不会误存。

**删除**：快照现在可以删。

- 列表每行右侧「删除」，预览弹窗底部「删除此快照」，都需二次确认；
- 删除后自动刷新列表；删的正好是当前预览项时一并关闭预览；
- 主进程 \deleteSnapshot\ 对不存在的 id 返回 \NOT_FOUND\。

**验证**：新增 2 条用例（删除只影响目标快照、删除不存在 id 报错），全量 **14 文件 / 101 用例** 全绿，\	sc\ / \eslint\ / \uild\ 通过。
## 九、W2.4 恢复不再自动留档

**反馈**：恢复版本时自动生成一条「恢复前」备份，属于替作者做决定，也让列表变成过程垃圾。

**改动**：

- \estoreSnapshot\ 去掉 pre_restore 写入：恢复 = 直接覆盖当前正文，不再产生任何新快照；
- 删除 \PRE_RESTORE_KEEP\ / \prunePreRestore\ / \hasSnapshotWithHash\ 三个为自动留档服务的实现；
- 确认文案改为「会直接覆盖、不可撤销；如需保留请先留个快照」，把决定权交回作者；
- 面板加一行提示「恢复会直接覆盖当前正文，不自动备份」；
- 旧版本已经堆积的「恢复前」记录：面板检测到就显示「还有 N 条旧版记录 · 一键清理」，确认后按章节删除，**不清其它快照**。

**保留**：崩溃恢复里「留档并丢弃」仍会把草稿存成手动快照——那是用户在弹窗里明确点的动作，不属于自动行为。

**验证**：全量 14 文件 / **99 用例** 全绿，新增「恢复不产生任何新记录」「旧版记录可清理且保留其它快照」两条。
