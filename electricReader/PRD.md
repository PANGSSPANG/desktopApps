## 1. 背景与问题

### 1.1 产品定位

electricReader 是一个**只做阅读**的桌面应用：把本地 EPUB / TXT 收进一个书架，打开即读，进度、排版与状态全部留在本机。

一句话：**把「找书 → 打开 → 接着读」压缩到两次点击。**

它**不是**：书城、云书架、笔记/批注工具、AI 摘要工具、格式转换器、电子书管理器（Calibre）。

### 1.2 要解决的四个问题

| 问题 | 具体表现 | 现有工具为什么不够 | electricReader 的回答 |
| --- | --- | --- | --- |
| 找不到上次读到哪 | 多本书并行，靠记忆翻页 | 系统阅读器不记录、或只记单本 | 统一书库 + 全局进度 + 「继续阅读」置顶 |
| 中文排版难调 | 字号、行距、版心、字体各调一次 | 阅读器选项少、不跟随主题 | 字号/行高/版心/字体/缩进 5 组设置，全局生效 |
| TXT 难读 | 没有目录、几十万字一坨 | 多数阅读器只支持 EPUB | TXT 自动识别编码与章节，转成可翻页的阅读文档 |
| 隐私顾虑 | 阅读记录、书单被上传 | 在线阅读器必须登录 | 完全离线、无账号、无遥测 |

### 1.3 差异化

1. **本地优先**：书籍副本、索引、封面都在 `%APPDATA%`，不联网也能用。
2. **中文优先**：GB18030 识别、中文数字章节、中文排版默认值。
3. **位置可恢复**：CFI + 文本片段双锚点，改字号/改版心/重启后仍回到原段落。
4. **克制的功能面**：没有社交、推荐、书城入口，界面只围绕「书架」和「阅读」两页。

### 1.4 首版边界（v1.1）

- 只支持 EPUB（2/3）与 TXT。
- 只做 Windows 10/11 x64 安装包，代码保持跨平台。
- 单窗口、单实例；不做多窗口对照。
- 不做 DRM、批注、书签、全文检索、TTS、云同步。

### 1.5 术语

| 术语 | 含义 |
| --- | --- |
| 书库 | 所有已导入书籍的集合，持久化在 `library.json` |
| 书籍副本 | 导入时复制到 userData 的文件，按内容 SHA-256 命名 |
| Locator | 阅读位置的跨进程契约，含 href / CFI / 进度 / 文本片段 |
| 阅读状态 | `unread` 未读 / `reading` 在读 / `finished` 已读 |
| 版心 | 正文最大宽度，对应设置项 `maxWidth` |

## 2. 目标用户

| 分层 | 特征 | 主要诉求 | 优先级 |
| --- | --- | --- | --- |
| 本地书库型读者 | 手里有大量 EPUB/TXT，讨厌云书架 | 一个地方管书、打开快、进度不丢 | 最高 |
| 中文网文/轻小说读者 | TXT 多、章节多、长时间连续阅读 | TXT 目录、深色主题、字号可调 | 高 |
| 隐私敏感读者 | 不接受账号与上传 | 离线、无遥测、数据可自行备份 | 高 |
| 轻度学术/技术阅读者 | PDF、批注、引用 | 划线与检索 | 低（首版不做） |

非目标用户：需要多端同步、社交书单、在线书城的用户。

## 3. 核心场景

### S1 导入并开始读

用户把 3 本 EPUB 和 1 本 TXT 拖进窗口 → 书架出现封面与标题 → 点击一本 → 打开阅读页 → 翻两页 → 关闭应用。再次打开，书架按最近阅读排序，顶部「继续阅读」直接回到刚才那页。

**验收**：拖入即导入；重复文件不重复入库；重启后进度、书架顺序、阅读状态一致。

### S2 调整排版

用户觉得字小、行距紧、版心太宽 → 打开设置面板 → 调字号、行高、版心、切换深色 → 正文即时重排，位置不跳回章节开头。

**验收**：调整后仍停留在原段落；设置重启后保留；跟随系统开关生效。

### S3 TXT 阅读

用户导入一本 2MB 的 GBK TXT → 自动识别编码与「第X章」标题 → 目录列出 120 章 → 从第 1 章读到第 37 章 → 重启后回到第 37 章。

**验收**：目录层级正确；章节标题可读；翻页无乱码；进度可恢复。

### S4 文件被移动

用户清理磁盘时删掉了 `books/` 下的副本 → 书架标记「文件缺失」→ 用户点击重新定位，选择原书 → 应用校验内容 hash 一致后恢复，阅读进度保留。

**验收**：hash 不一致时拒绝并提示；一致时恢复且进度不丢。

### S5 隐私与离线

用户在断网环境使用一整天。应用不发起任何网络请求，不产生账号、不上传书名或阅读记录。

**验收**：断网可用；无遥测请求；日志不含书名/正文。

## 4. 功能范围

### 4.1 优先级定义

- **P0**：首版必须可用，缺失即阻塞发布。
- **P1**：首版不做，架构预留。
- **不做**：明确不进产品方向。

### 4.2 P0 功能明细

#### F-01 书架

| 能力 | 说明 |
| --- | --- |
| 导入 | 文件对话框多选 / 拖拽；支持 `.epub` `.txt`；单次 ≤ 500 个 |
| 去重 | 按内容 SHA-256；同内容不同文件名视为同一本 |
| 展示 | 封面、标题、作者、格式、进度、状态；网格/列表两种视图 |
| 筛选 | 全部 / 在读 / 未读 / 已读，带数量 |
| 排序 | 最近阅读优先；从未读过的按导入时间 |
| 继续阅读 | 顶部展示最近在读且文件存在的一本 |
| 删除 | 二次确认；删除索引、书籍副本与封面 |
| 重定位 | 文件缺失时可重新选择，校验 hash |
| 状态 | 手动切换未读/在读/已读 |

#### F-02 阅读器

| 能力 | 说明 |
| --- | --- |
| EPUB | EPUB 2 / 3；封面、目录、spine 顺序 |
| TXT | UTF-8 / UTF-16 / GB18030；章节拆分；内存转 EPUB |
| 翻页 | 键盘、点击热区、横向滚轮；三种模式可切 |
| 目录 | 抽屉式，多级，当前章节高亮，点击跳转 |
| 进度 | 百分比 + 章节名；1.2s 防抖保存；退出前 flush |
| 结束 | 读到末页自动标记已读 |
| 错误态 | 文件缺失、损坏、DRM、过大均有可操作提示 |

#### F-03 排版与主题

| 能力 | 选项 |
| --- | --- |
| 字号 | 100 / 115 / 130 / 145 / 160 |
| 行高 | 1.5 / 1.7 / 1.9 |
| 版心 | 640 / 720 / 820 / 960 px |
| 字体 | 衬线 / 无衬线 |
| 首行缩进 | 开 / 关 |
| 主题 | 浅色 / 羊皮纸 / 深色 / 跟随系统 |

#### F-04 数据安全

| 能力 | 说明 |
| --- | --- |
| 原子写 | 索引写入不产生半截文件 |
| 备份 | 每次写入保留 `.bak`；损坏时自动恢复 |
| 归档 | 无法解析的索引改名保留，不删除 |
| 路径安全 | 封面协议只接受合法书籍 id，杜绝路径穿越 |

### 4.3 页面与信息架构

```
书架（/）
├─ 顶栏：品牌 / 书数 / 主题菜单 / 导入
├─ 继续阅读
├─ 筛选 + 视图切换
└─ 书籍网格或列表
阅读页（/read/:bookId）
├─ 工具栏：返回 / 书名 / 进度 / 状态 / 目录 / 设置
├─ 正文（epub.js iframe）
├─ 底部：上一页 / 章节名 / 百分比 / 下一页
├─ 目录抽屉
└─ 设置面板
```

### 4.4 全局业务规则

- **书籍身份 = 内容 hash**：改名、移动不会产生重复；内容变化即视为另一本书。
- **进度 = Locator**：CFI 优先，文本片段兜底；任何设置变化不得重置进度。
- **状态自动流转**：打开并保存进度 → `reading`；达到 99% → `finished`；手动可覆盖。
- **文件缺失不删除记录**：只标记，等待用户重定位或主动删除。
- **错误必须可操作**：文案说明「发生了什么 + 能做什么」，不暴露堆栈。

### 4.5 P1（架构预留，不在首版）

- 批注 / 书签 / 划线 / 笔记导出
- 书内全文检索
- PDF / MOBI / AZW3
- 阅读统计（时长、连续天数）
- 标签 / 收藏夹 / 智能书架
- OPDS / 局域网传书
- 多窗口对照、分屏
- 自动更新与代码签名
- 迁移到 SQLite 以支撑万本级书库

### 4.6 明确不做

- 在线书城、账号、云同步、社交分享
- DRM 破解
- 格式转换（EPUB ↔ MOBI 等）
- TTS / AI 摘要 / 翻译
- 阅读时长上报或任何遥测

## 5. 成功标准

### 5.1 功能完成度

- P0 四项能力全部可用，无阻塞级缺陷（打不开、丢进度、丢书）。
- 三条主链路可复现：导入→阅读→重启续读；改排版→位置不丢；删除→文件清理。

### 5.2 性能指标

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| 冷启动到书架可交互 | < 1.5s | 50 本书、含封面 |
| 打开 10MB EPUB | < 2s | 本地 SSD |
| 翻页 | < 100ms | 连续 100 次取 P95 |
| 改字号后重排 | < 500ms | 50 万字书籍 |
| 书架滚动 | ≥ 55fps | 200 本书 |
| 进度保存 | 不阻塞翻页 | 观察输入延迟 |

### 5.3 数据安全

- 强杀进程后重启：已保存进度 100% 保留，最坏丢失 ≤ 1 次防抖窗口（1.2s）。
- 索引损坏：能从 `.bak` 恢复；两份都坏时保留归档文件并给出提示。
- 删除书籍：索引、副本、封面三者一致清理，无残留。
- 无任何网络请求。

### 5.4 质量

- `pnpm typecheck` 0 错误；`pnpm test` 48 条全绿；`pnpm test:e2e` 5 条全绿。
- 无 `any`（第三方类型适配处除外并注明原因）。
- 关键路径（导入、进度、重定位）必须有测试。

### 5.5 交付物

- Windows NSIS 安装包（x64）。
- README、PRD、技术方案、开发规范。
- 单元/集成测试与 E2E 用例。

## 6. 约束与假设

- 【假设】用户书籍以 EPUB / TXT 为主，单本 ≤ 200MB，书库 ≤ 2000 本。
- 【假设】单机单用户，不需要并发写与多端同步。
- 【假设】首版只验证 Windows 10/11，macOS/Linux 仅保证代码可编译。
- 【假设】不做代码签名，安装时 SmartScreen 提示属预期。
- 【推断】JSON 索引在千本级仍可接受；万本级需迁移 SQLite（见技术方案 §11）。
- 【推断】epub.js 对复杂固定版式（fixed-layout）支持有限，首版按流式排版处理。
- 【推断】TXT 转 EPUB 的内存开销与文件大小线性相关，200MB 上限是安全边界。
